# AndroidOptimizer

Безопасный Android-оптимизатор на Kotlin + Jetpack Compose (Material 3).
Принцип: только реальные данные устройства и системные экраны — никакой имитации «очистки»
и никаких изменений системы без подтверждения пользователя.

## v0.4
- Полный список пакетов (в т.ч. служебные системные: Play Services, WebView и т.п.): фильтры «Пользовательские / Системные / Все», значки «Системное», «Отключено», «Служебное», «Не используется».
- Размеры приложений и кэша (StorageStatsManager, нужен Usage Access): сортировка по размеру, топ приложений, разбивка хранилища на «Приложения / Кэш / Прочее / Свободно».
- Новый дизайн обзора: сводная карточка со статусом и анимированными кольцами (ОЗУ, хранилище, батарея), обновлённые карточки рекомендаций, более крупные скругления и акценты в типографике.
- Подсказка о большом кэше (от 1 ГБ).

## v0.3
- Вкладка «Профили»: «Экономия заряда», «Обычный», «Долгий экран». Профили меняют только таймаут экрана и яркость и требуют специальное разрешение «Изменение системных настроек» (выдаётся вручную). Перед применением показывается, что именно изменится.
- Журнал изменений: каждое применение записывает снимок «до»; последнее изменение можно отменить одним нажатием (откат строго по порядку).

## v0.2
- Обзор: ОЗУ, хранилище, батарея (заряд, статус зарядки, температура) с цветовой индикацией уровня.
- Рекомендации строятся из реальных данных и ведут в системные экраны (освобождение места, расход заряда, Usage Access).
- Вкладка «Приложения»: последний запуск, экранное время за 7 дней, поиск, сортировка, фильтр системных, переход в «О приложении» и в системный диалог удаления.
- Полный список пакетов требует `QUERY_ALL_PACKAGES`: Google Play ограничивает это разрешение, поэтому приложение рассчитано на прямую установку (сайдлоад).
- Светлая/тёмная тема, динамические цвета (Android 12+), edge-to-edge, адаптивная иконка (в т.ч. монохромная).
- Русская и английская локализации (с корректными русскими формами множественного числа).
- Чистая доменная логика (`domain/`) покрыта unit-тестами; Gradle wrapper; CI-сборка на GitHub Actions.

## Сборка
```
./gradlew testDebugUnitTest assembleDebug
```
Нужны JDK 17 и Android SDK (compileSdk 35). APK: `app/build/outputs/apk/debug/`.
CI (`.github/workflows/build.yml`) запускает тесты и сборку на каждый push.

## Структура
- `domain/` — модели, правила рекомендаций, сортировка и фильтры (без Android-зависимостей, покрыто тестами).
- `data/` — чтение состояния устройства и статистики приложений.
- `ui/` — Compose-экраны, тема, ViewModel.

## Ограничения (честно)
- «Прочее» в разбивке хранилища — это остаток занятого места (система, фото, загрузки), а не измеренная величина; приложения и кэш — данные системы.
- «Давно не использовалось» опирается на `UsageStatsManager`: система хранит месячную статистику около 6 месяцев, данные приблизительные.
- Вибро-отклик намеренно не включён в профили: системная константа `HAPTIC_FEEDBACK_ENABLED` объявлена устаревшей, а её работу на новых версиях Android проверить нельзя.
- Свободная ОЗУ в Android по природе мала (кэш приложений) — предупреждение показывается только при флаге `lowMemory` или остатке < 8%.

## План
1. Shizuku/ADB функции с проверкой доступности (там же появится профиль «Производительность»: без повышенных прав он ничего реально не ускорит, поэтому его сейчас нет).
2. Root-модуль как отдельный повышенный режим.
3. Расширение журнала на действия Shizuku/root.

> AndroidOptimizer не должен применять сомнительные build.prop-твики или отключать критические системные компоненты без проверки и возможности отката.
